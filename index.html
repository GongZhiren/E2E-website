Abstract

Model merging folds several models fine-tuned from a shared checkpoint into a single multi-task model — no original data, no joint retraining. But naively combining weights (averaging, task arithmetic) causes interference: every task loses accuracy.

We reframe merging as a functional objective: on each task's unlabeled inputs, make the merged model's representation match that task's expert. This turns merging from "how to combine weights" into "what the merged model should do". E2E-Merge optimizes this end-to-end.

The theory unifies the field: the strongest closed-form mergers (RegMean / RegMean++) are exactly the local, layer-wise approximation of this objective; Fisher merging is its diagonal analogue; averaging ignores the geometry entirely. Optimizing the objective directly closes the gap they leave — recovering up to 99.9% of fine-tuned accuracy and widening its lead as tasks grow.

The Problem · Interference

Why merge at all?

Hubs host thousands of experts — one model per task. Serving a separate network per task is expensive; folding them back by retraining needs every task's data at once, which is often private or gone. Merging removes both costs — if it can be done without losing accuracy.

Weights aren't the right unit

Task vectors τ_a = θ_a − θ₀ conflict when summed, so each task degrades. The real damage is functional: the merged model's outputs drift from each expert's — concentrated in the output-relevant directions that per-layer weight surrogates cannot see.

The insight: match functions, not weights

A good merge should behave like the experts it replaces. So optimize the discrepancy between the merged model's function and each expert's function directly — end-to-end, where interference actually lives.

Method

A single functional objective

For merged encoder g_θ and experts g_{θₐ}, minimize the representation discrepancy on each task's own inputs:

minθ   Σa   Ex∼Da   ‖ gθ(x) − gθa(x) ‖²

No labels — the target is the teacher's representation. "Matching functions" means optimizing what the merged model computes, not what its weights look like.

The unifying theory

  • RegMean / RegMean++ = the local, first-order, layer-wise approximation of this objective.
  • Fisher merging = its diagonal-metric analogue; Averaging / Task Arithmetic ignore the metric.
  • All are degenerate special cases of the one objective E2E-Merge optimizes globally.

How E2E-Merge optimizes it

  • Start from a task-arithmetic init (θ₀ + α·Στₐ, α=0.3); teachers frozen (stop-gradient).
  • Each step: sample a task, a fresh minibatch, and match the expert's representation.
  • Streaming batches track the full task distribution; AdamW + gradient clipping, label-free.

Bounded-memory variant

  • Merge transformer blocks group-by-group from the input side, feeding each group the merged network's real activations.
  • Peak activation memory = one group's — 13 vs 31 GB on ViT-L/14 — and even a single-block group already beats RegMean++.

Step 1 · Init

Warm-start from task arithmetic (θ₀ + 0.3·Σ task vectors) — a good, fast starting point.

Output: a merged model near the experts, ready to refine.

Step 2 · Match

Stream fresh minibatches per task; make the merged model reproduce each frozen expert's representation.

Output: end-to-end functional agreement, no labels used.

Step 3 · Ship

A single merged model — one network that behaves like all the experts it replaces.

Result: near fine-tuned accuracy at one model's cost.

Reading the results

  • A single merged model reaches the individual fine-tuned accuracy — 94.3 = 94.3 on ViT-L/14.
  • The margin over the best baseline widens with task count: +2.6 (2 tasks) → +6.0 (8) → +13.7 (20).
  • It also grows as the backbone weakens — the advantage tracks interference, not model scale.
  • Held-out tasks: leads on seen tasks with no trade-off on unseen ones.

Why It Works

Per-layer optimality ≠ end-to-end optimality

RegMean++ and E2E-Merge have almost identical per-layer residuals — yet their end-to-end residuals differ 2.4× (0.23 vs 0.55, vs 0.83 for task arithmetic), and that ordering matches accuracy exactly (90.2 > 84.2 > 67.6). Small per-layer errors compound through depth; only an end-to-end objective controls what actually reaches the output.

The induced-metric ladder

On ViT-B/32 (8 tasks), each step toward the exact functional objective adds accuracy:

No metricDiagonalPer-layer isotropicExact metricE2E-Merge

The exact metric buys +2.7 over isotropic RegMean; re-evaluating the nonlinearity end-to-end buys a further +3.3.

What matters (ablations)

  • Representations > logits: matching the embedding beats distilling logits by 2.5 points.
  • Reaching the optimum matters: anchoring to the init hurts (−4.2) — the gain is the end-to-end solution, not staying near start.
  • Data-efficient: at RegMean's own 256-sample budget it already leads by +1.7.
  • Learning rate is the only sensitive knob; accuracy rises with steps and saturates (no overfitting).

Efficiency & Scope

A one-time, offline merge

  • ~13 minutes on a single GPU to merge 8 tasks on ViT-L/14 — done once, offline.
  • Deployment cost is a single model, identical to any other merged model.
  • Bounded-memory block-wise variant: 13 vs 31 GB on ViT-L/14, still above every baseline.
  • Needs only unlabeled task inputs — heavier than closed-form RegMean, far cheaper than joint training.

Honest scope

  • Main evaluation is CLIP vision; a Flan-T5 GLUE probe shows the objective transfers beyond vision — broader language / multi-modal study is the natural next step.
  • The method completes prior work rather than breaking with it: RegMean is a layer-wise approximation of the same objective.
  • Requires a one-time gradient pass over unlabeled inputs (not a pure closed form).
